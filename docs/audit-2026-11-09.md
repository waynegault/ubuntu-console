## Critical findings

Status is stated per finding: **FIXED** in this pass, or **OPEN**.

### C1. [FIXED] Incremental update accumulates stale memory nodes and never refreshes fields

`GraphBuilder.add_node` keeps the **first** node seen and only unions lineage:

```python
existing = self._nodes.get(node.id) if node.id else None
if existing is not None:
    existing.merge_sources(node.sources)
    return existing          # new label/content/concepts discarded
```

`incremental_update` merges the persisted graph **before** the fresh memory graph
(`scripts/kgraph/update.py:54-60`, `:78-88`), so an edited memory keeps its old
label and content. `prune_ast_nodes()` removes only `ast_*` ids. Deleted memories
and stale chunks are never subtracted, and because chunk ids hash the chunk text,
every edit orphans `chunk:<oldhash>` plus its edges forever. The package has an
`update` command that is not idempotent in the sense its name implies.

**Landed:** `Graph.prune_memory_nodes()` removes every memory-derived node (by id
prefix, `origin="memory_db"`, or a memory/chunk/file source) and its incident edges
before the fresh import; user and AST nodes are preserved. `_MemoryStoreIngest`
now stamps `origin="memory_db"` on the nodes it emits, so future graphs carry the
ownership marker. Acceptance held: the new test seeds `memory:mem-1` with an old
label, imports a changed row, and reads the NEW label with the user node intact.

### C2. [FIXED] Registry relationship edges dangle

Entity nodes are created as `entity:{kind}:{slug}` (`memory_import.py:2039`), but
relationships emit `entity:{entity_id_a}` where `entity_id_a` is the entity UUID
(`memory_import.py:2129-2136`). `GraphBuilder.add_edge` does not check endpoints,
and the test at `tests/test_kgraph.py:2443` enshrines the dangling pair for a
fixture that has no entity rows. Every relationship edge can therefore be
invisible to any view that resolves endpoints.

**Landed:** `_import_registry_entities` now returns the UUID→node map alongside the
normalised-name map; `_import_registry_relationships` resolves through it and skips
plus logs unresolved rows. The endpoint invariant is also enforced at
`GraphBuilder.build()` and `save_to_graph_db` (and repaired, with a warning, when
loading a legacy graph), so a future emitter cannot reintroduce a dangling edge.

### C3. [FIXED] CI push/nightly never run 17 Python suites

`.github/workflows/ci.yml:451` and `nightly.yml` name 21 test files by hand. These
tracked suites run only on PR/dispatch (`python-unit`, `if: github.event_name !=
'push'`), i.e. never on the direct-to-main flow this repo uses:

`test_nas_bt_bridge.py`, `test_nas_collector_failures.py`, `test_llm_benchmark.py`,
`test_llm_task_quality.py`, `test_llm_outcome_cases.py`,
`test_llm_selection_report.py`, `test_kgraph_calibration.py`,
`test_kgraph_validation.py`, `test_heavy_job_gate.py`, `test_gguf_metadata_add.py`,
`test_source_import.py`, `test_tool_modules.py`, `test_bats_bridge.py`,
`test_bats_unittest.py`, `test_grpo_vram_probe.py`, `test_kv_recall_probe.py`,
`test_oc_restart_check.py`.

This is the "invisible to test outcomes" shape at its purest: the code is tested,
but not on the lane that publishes it.

**Landed:** both bridge modules carry `pytest.mark.host_coupled`; the push and
nightly Python steps now run `pytest -m "not host_coupled"` over the configured
testpaths. The push lane installs the pinned bats because collection imports the
bridges. `--collect-only` reports 898 selected tests (up from the hand list's
subset), and the selection passes. A future `tests/test_*.py` is picked up with no
workflow edit; the remaining hole is a meta-test that would fail if a new suite
were ever marked host-coupled unnecessarily — not needed for coverage.

### C4. [FIXED] The bench lock is unlinked while it is the mutex

`scripts/11e-llm-model.sh:3386-3397` opens and `flock`s the file, then
`:3469-3473` (and two siblings) unlock, close, and `rm -f` it. Unlinking a held
flock defeats mutual exclusion: a waiter blocked on the old inode can be granted
while a third process creates a new file and locks that. It also breaks the
existence-based probes in `bin/llama-watchdog.sh:754` and `11e:2765` — the exact
marker race that file's own header records.

**Landed:** flock moved to a never-unlinked `${lock}.mutex`; the old lock path is
the PID marker, so every existing existence probe (watchdog, gpu-busy, health,
`model stop`) keeps its meaning. `train-timeout-runner` uses the same mutex, and
the stale-lock reaper probes the mutex before falling back to the cooperative PID.
E1 refuses a second bench while the mutex is held; E2/E7 and all five
train-runner cases pass. E7 caught that `-L` overrode the marker after the mutex
had been derived — fixed by moving the derivation after option parsing.

### C5. [FIXED] Silent partial graph on import failure

`_load_from_memory_db_conn` wraps the whole chunk phase in
`except sqlite3.Error: logger.warning(...)` and returns the file-only graph
(`memory_import.py:1269-1273`). `incremental_update` separately catches
`(OSError, ValueError, KeyError)` for each memory DB and for AST extraction, logs a
warning, and **saves** the merged result. A failed import therefore produces a
graph that looks complete, and the warning is the only trace.

**Landed (decision: fail by default):** `incremental_update` collects every input
failure, raises `UpdateError` before the save unless `allow_partial=True`, and
`kgraph update --allow-partial` is the documented opt-in. The inner
`except sqlite3.Error` that produced a file-only graph is gone, so the failure
reaches that decision point instead of being swallowed one level down.

### C6. [FIXED] The contract checker passes when its read-back axis cannot run

`tools/contracts_checkers/state.py:523-540` sets `counts["checked"] = False` and
prints `NOT CHECKED` when `command-contracts.yaml`, commands, or
`scripts/_module-list.sh` are missing — then `run_state` returns 0 if no other
problem was found. `continuity.py:337-350` does the same when the module surface
cannot be derived (`if surface and command not in surface`). `derived.py` returns
`EXIT_CANNOT_RUN` for the same class of missing input, so the family takes two
opposite postures.

**Landed:** `state` returns `EXIT_CANNOT_RUN` when the read-back witnesses were not
checked; `continuity` carries a `surface_checked` flag from
`validate_decision_records` and returns the same when the `commands:` surface could
not be derived. Two new cases assert both, including a temp repo with a valid state
contract but no command contracts.

### C7. [FIXED] Concept filtering disables itself when its config is missing

`constants.py:76-95` loads `config/concept-aliases.json` at import; on failure it
logs one warning and returns `{}`. The module's own comment says "a warning nobody
reads is the same as no warning", yet the graph then imports with all filtering
(scaffolding labels, aliases, low-value concepts, agent roles) silently off. The
same loader is also called at import time, so the I/O happens for every consumer.

**Landed:** `load_concept_config` raises `ConceptConfigError` with the candidate
paths after refusing a non-object or a mapping missing the required keys. The
packaged-tool path (`sys.prefix/config`) is still tried; absence there is now a
broken install, not a degraded mode.

- **Pydantic coverage is centred on kgraph.** `tools/*.py`, `scripts/check_ci_status.py`,
  `scripts/oc-health-check.py`, and the NAS collectors parse external JSON into raw
  dicts. Concrete silent shapes: `check_ci_status` trusts run dicts; `oc-health`
  now guards the root but not nested fields; `continuity.py` parses decision
  frontmatter with a regex while `yaml` is already imported, so a YAML block list
  for `commands:` silently yields no commands.
- **Validation findings are raw dicts.** `validate_graph` returns `list[dict]` with
  free-string severities and a dynamically named `*_idx` key. A
  `ValidationFinding`/`ValidationResult` model would make severity a closed enum and
  the CLI/report consumers typed.
- **Mention edges lack the guard claims already have.** `_import_registry_mentions`
  emits `memory:{id}` → entity without checking `has_node`, unlike
  `_import_registry_claims` (`memory_import.py:2222`). A mention of a filtered
  (archived) memory therefore produces a dangling edge. Add the same guard, and the
  endpoint invariant proposed for `GraphBuilder`.
- **Life-index input is unvalidated.** `load_life_index` does `payload.get("records", [])`

  tuple. A `CanonicalConceptFile` model fixes it.

  becomes a `TypeError` reported as an internal error. Validate and return `-32602`.

  `except ImportError`, then "no communities" with no reason. Log once.

- **Thirteen copies of `isinstance(dict) → Graph.from_dict`** across the package; one
  `as_graph()` helper would make the boundary explicit and consistent.
- **`save_to_graph_db` is delete-then-insert** in one transaction. It is crash-safe,

## Decisions resolved (2026-11-10)

1. **Partial import policy — fail by default.** `UpdateError` is raised before the
   save; `--allow-partial` is the explicit, documented opt-in and logs that the
   saved graph is INCOMPLETE. (C5)
2. **Memory node identity — prune and re-add.** `Graph.prune_memory_nodes()` runs
   before the fresh import; user and AST nodes are preserved. (C1)
3. **Relationship identity — keep `entity:{kind}:{slug}` and resolve UUIDs to it.**
   The entity phase returns the UUID→node map; unresolved endpoints are skipped and
   named. (C2)
4. **Host-coupled tests — mark and exclude.** Both bridges carry
   `pytest.mark.host_coupled`; push/nightly run `-m "not host_coupled"`. (C3)
5. **Registry tolerance — fail closed at ingestion.** A non-numeric `value_score`
   drops the row with a named warning; the stored `float | str | None` type stays
   only so already-written graph data remains readable. (recommendation accepted)

No policy decision remains open from this audit. C4, C6 and C7 are engineering
work with clear acceptance tests, not choices.
